title: The CLI
description: sandbox-cli — the whole API from a terminal, with honest exit statuses and safe retries built in.
---

:::caution[Simulated money only]
Everything `sandbox-cli` does here is against the simulated stack: it prints
`SIMULATED MONEY ONLY` on every run and refuses a key that is not `sk_sim_…`.
:::

`sandbox-cli` covers the whole API — payments, the ledger, checkout sessions, webhooks,
events, the scenario library and dataset resets — with the exit status saying what really
happened. It reads `PS_API_URL` (default `http://127.0.0.1:56080`) and `PS_API_KEY` from the
environment; `--json` prints the API's own JSON instead of words.

## Guardrails first

The CLI is the first place the sandbox-only contract is enforced: a key that isn't
`sk_sim_…` is refused before anything is sent, a real processor's host is refused, a
non-loopback `--api-url` needs `--allow-non-local`, and plain `http://` to a remote host
needs `--allow-plain-http`. `--ca-cert` trusts a private CA for a self-hosted sandbox.

## Exit statuses tell the truth

| Exit | `Ended` | Meaning |
|---|---|---|
| `0` | done | The operation succeeded (or the read finished). |
| `1` | refused | The API refused — an auth, scope or validation error. |
| `2` | usage | Bad input: a non-`sk_sim_` key, a bad amount, an unknown scenario. |
| `3` | declined | The simulated network declined, or refused to execute. |
| `4` | uncertain | The answer is not known — check before retrying or fulfilling. |
| `5` | unreachable | The API could not be reached at all. |

`--idempotency-key` reuses a key to retry a request whose answer you lost — the same key,
never a fresh one.

## A clean slate: dataset reset

`reset` archives the project's whole dataset and opens a new, empty epoch — nothing is
deleted, but the reset needs the project's slug typed as confirmation (without `--confirm`
it asks interactively):

```sh run=cli
cargo run -q -p sandbox-cli -- --json reset --confirm my-store
```

```json output=cli
{
  "project": {
    "dataset_epoch": 2,
    "id": "01a1f3a4-a804-74fb-9e8a-c24a9a03c176",
    "name": "My store",
    "slug": "my-store"
  },
  "reset": {
    "archived_payments": 9,
    "from_epoch": 1,
    "note": "nothing was deleted: the earlier epoch's journal, payments and events are archived",
    "to_epoch": 2
  },
  "simulated": true
}
```

The earlier epochs' journals, payments and events stay archived; the project's keys keep
working against the new epoch.
